# Asveli backend

Один маленький сервер для всех четырёх заглушек (asveli.pl / .eu / .com / .shop):

- **`POST /api/subscribe`** — принимает email с сайтов (CORS только для ваших доменов, каждый сайт может подписывать только на себя), хранит в SQLite без дублей.
- **Хранилище файлов на Google Drive API** (ваши 400 ГБ) вместо S3. Файлы лежат в одной папке на Drive под случайными именами и **никогда не публикуются на самом Drive** — всё отдаётся через этот сервер, поэтому права доступа решаете вы.
- **Админка** — подписчики (поиск, экспорт CSV, удаление), файлы (загрузка с прогрессом, публичные ссылки, временные подписанные ссылки как presigned URL в S3, отзыв ссылок), 2FA, смена пароля, журнал действий. **Из интернета админка недоступна ни по домену, ни по порту**: она открывается только через SSH-туннель (раздел 4).
- **HTTPS** через nginx + Let's Encrypt, запуск в Docker.

```
                        ИНТЕРНЕТ
                           │  открыты только 22, 80, 443
              ┌────────────▼────────────┐
              │ nginx :443 (HTTPS)       │   /admin и /api/admin → 404
              └────────────┬────────────┘
                           │ 127.0.0.1:3000
 ┌─────────────────────────▼─────────────────────────────────────────────┐
 │ СЕРВЕР   Node:  PUBLIC listener :3000   /api/subscribe, /f/…, /s/…     │
 │                 ADMIN  listener :3001   панель + admin API  ◀── только │
 │                 (127.0.0.1)                                   loopback │
 │          SQLite (/data) · Google Drive API                             │
 └─────────────────────────▲─────────────────────────────────────────────┘
                           │ ssh -L 3001:127.0.0.1:3001   (шифрованный туннель)
                      ВАШ КОМПЬЮТЕР → http://localhost:3001/admin/
```

Админский код вообще не загружен в публичный listener: у публичного порта нет ни маршрутов админки, ни её статических файлов, ни обработки сессий.

## 1. Локальный запуск (без Google, для проверки)

```bash
npm ci
cp .env.example .env            # в .env поставьте: NODE_ENV=development, STORAGE_DRIVER=local
node --env-file=.env scripts/create-admin.js aleks     # спросит пароль (≥12 символов)
node --env-file=.env src/server.js
# публичное API: http://localhost:3000   админка: http://localhost:3001/admin/
npm test                         # 34 теста: изоляция админки, авторизация, CSRF, 2FA, загрузка, Range, ссылки, лимиты, Drive-драйвер
```

## 2. Подключение Google Drive (один раз)

> Важно: **сервисный аккаунт здесь не подходит** — у него своя квота (≈0 ГБ), а не ваши 400 ГБ. Используется OAuth вашего аккаунта.

1. <https://console.cloud.google.com> → создайте проект → **APIs & Services → Library → Google Drive API → Enable**.
2. **OAuth consent screen** → тип *External* → заполните название и email → в *Scopes* добавьте `…/auth/drive.file`.
3. На экране согласия нажмите **Publish app → In production**. Если оставить статус *Testing*, refresh-токен **умирает через 7 дней**. Скоуп `drive.file` не требует верификации Google.
4. **Credentials → Create credentials → OAuth client ID → тип *Desktop app***. Скопируйте Client ID и Client secret в `.env`.
5. Получите токен (запускать на своём компьютере, где есть браузер):
   ```bash
   GOOGLE_CLIENT_ID=… GOOGLE_CLIENT_SECRET=… npm run drive-token
   ```
   Откройте выведенную ссылку, войдите в аккаунт с 400 ГБ, разрешите доступ. Скрипт напечатает `GOOGLE_REFRESH_TOKEN=…` → вставьте в `.env` и поставьте `STORAGE_DRIVER=drive`.

Скоуп `drive.file` — минимально необходимый: приложение видит **только файлы, которые создало само** (папка `asveli-storage`), остальной ваш Drive и почта ему недоступны.

## 3. Деплой на сервер (Ubuntu/Debian) с HTTPS

DNS: добавьте A-запись `api.asveli.com` → IP сервера. (Другой домен — замените в конфигах `deploy/` и в `PUBLIC_BASE_URL`.)

```bash
# Docker + nginx + certbot + firewall
sudo apt install -y docker.io docker-compose-v2 nginx certbot ufw
git clone … asveli-backend && cd asveli-backend
cp .env.example .env && nano .env          # SESSION_SECRET, DATA_ENCRYPTION_KEY, PUBLIC_BASE_URL, Google-ключи
docker compose up -d --build

# админ-пользователь
docker compose exec api node scripts/create-admin.js aleks

# HTTPS, шаг 1: порт 80 + сертификат
sudo mkdir -p /var/www/certbot
sudo cp deploy/nginx-00-http.conf /etc/nginx/conf.d/asveli-http.conf && sudo nginx -t && sudo systemctl reload nginx
sudo certbot certonly --webroot -w /var/www/certbot -d api.asveli.com --deploy-hook "systemctl reload nginx"

# HTTPS, шаг 2: порт 443
sudo cp deploy/nginx-10-https.conf /etc/nginx/conf.d/asveli-https.conf && sudo nginx -t && sudo systemctl reload nginx

# файрвол: снаружи только SSH, 80, 443 (сначала проверьте порт SSH: sudo ss -tlnp | grep sshd)
sudo SSH_PORT=22 deploy/firewall-ufw.sh
```

Проверка: `curl -I https://api.asveli.com/api/health`. Сертификат продлевается автоматически (таймер certbot).

### Подключить заглушки

В каждом из 4 HTML-файлов в блоке `CONFIG` укажите:

```js
FORM_ENDPOINT: 'https://api.asveli.com/api/subscribe',
```

и убедитесь, что в `.env` в `ALLOWED_ORIGINS` перечислены `https://asveli.pl`, `https://asveli.eu`, `https://asveli.com`, `https://asveli.shop`.

### Публичные картинки для магазина

В админке → Файлы → отметьте «Публичный» → появится ссылка вида `https://api.asveli.com/f/<случайный-слаг>/имя.png` (картинки, mp4/webm, аудио отдаются inline с поддержкой Range; всё остальное — только как скачивание). Для публичных картинок на посещаемых страницах поставьте перед API Cloudflare (кэш), чтобы не упираться в лимиты Drive API.

## 4. Как открыть админку (только через SSH-туннель)

На **своём компьютере** (не на сервере):

```bash
./deploy/admin-tunnel.sh user@IP-сервера        # потом открыть  http://localhost:3001/admin/
./deploy/admin-tunnel.sh user@IP-сервера 8443   # если локальный 3001 занят → http://localhost:8443/admin/
```

Это то же самое, что `ssh -N -L 127.0.0.1:3001:127.0.0.1:3001 user@IP-сервера`. Закрыли терминал (Ctrl+C) — доступа к панели нет. Удобно прописать в `~/.ssh/config`:

```
Host asveli-admin
    HostName IP-сервера
    User user
    LocalForward 127.0.0.1:3001 127.0.0.1:3001
    ExitOnForwardFailure yes
    ServerAliveInterval 30
```

затем `ssh -N asveli-admin`. В панели всё равно нужен логин и пароль (+ 2FA): туннель защищает от доступа извне, но не заменяет вход.

**Как проверить, что снаружи админки нет** (с другого компьютера, не из туннеля):

```bash
curl -sI https://api.asveli.com/admin/          # → 404
curl -s  https://api.asveli.com/api/admin/me    # → {"error":"not_found"}
curl -m 5 http://IP-сервера:3001/               # → Connection refused / timeout
nmap -Pn -p 22,80,443,3000,3001 IP-сервера      # → открыты только 22, 80, 443
```

**Если что-то не открывается:**
- `421 Misdirected request` — вы зашли по другому имени (не `localhost` / `127.0.0.1`). Это защита от DNS-rebinding; нужное имя можно добавить в `ADMIN_ALLOWED_HOSTS`, но для туннеля это не требуется.
- `bind: Address already in use` — локальный порт занят, возьмите второй аргумент скрипта (`8443`).
- Контейнер не стартует с «ADMIN_HOST … would expose the admin panel» — вы изменили `ADMIN_HOST` или `ports:` в `docker-compose.yml`. Верните как было: сервер намеренно отказывается запускаться в небезопасной конфигурации.

**Рекомендации по SSH на сервере** (`/etc/ssh/sshd_config`): `PasswordAuthentication no` (только ключи), `PermitRootLogin no`. По желанию — отдельный пользователь только для туннеля:

```
Match User asveli-tunnel
    AllowTcpForwarding local
    PermitOpen 127.0.0.1:3001
    PermitTTY no
    X11Forwarding no
    ForceCommand /bin/false
```

## 5. Что сделано для безопасности

| Угроза | Мера |
|---|---|
| **Доступ к админке снаружи** | Админка на **отдельном порту 3001 только на 127.0.0.1**; в публичном listener нет админских маршрутов; nginx не проксирует её и отвечает 404 на `/admin`, `/api/admin`; Docker публикует порт как `127.0.0.1:3001`; файрвол закрывает 3000/3001; сервер **отказывается стартовать**, если `ADMIN_HOST` не loopback или `ADMIN_PORT == PORT` |
| DNS-rebinding (чужой сайт, чей домен «переведён» на 127.0.0.1) | Панель отвечает только на `Host: localhost / 127.0.0.1 / [::1]` — иначе `421` |
| Подбор пароля | scrypt (N=2¹⁵), блокировка аккаунта на 15 мин после 5 ошибок (**счётчик атомарный — параллельные попытки не обходят блокировку**), лимит попыток по IP, одинаковый ответ и время для несуществующего логина |
| Кража аккаунта | Опциональная 2FA (TOTP), секрет шифруется AES-256-GCM, **код одноразовый даже при параллельной отправке**, смена пароля закрывает все остальные сессии |
| Кража сессии | Случайный токен 256 бит, в БД только его SHA-256; cookie `HttpOnly; SameSite=Strict`; простой 60 мин, максимум 12 ч; новая сессия после входа/2FA (нет session fixation) |
| CSRF | SameSite=Strict + **same-origin по `Origin == Host` (с портом)** + `Sec-Fetch-Site` + токен `X-CSRF-Token` на каждый изменяющий запрос. Порт важен: `localhost:8080` и `localhost:3001` — один и тот же «сайт» для SameSite, поэтому одной cookie мало |
| XSS | Строгий CSP (`script-src 'self'`, без inline), админка не использует `innerHTML` (проверено в браузере на враждебных email и логинах); файлы отдаются с `nosniff`, `CSP: sandbox`, не-медиа — только `attachment` |
| Утечка файлов | Файлы на Drive не расшарены; доступ только через сервер; публикация — явная, слаг 128 бит; временные ссылки подписаны HMAC, имеют срок и мгновенно отзываются |
| Подмена имени файла | Из имён удаляются управляющие, bidi- и zero-width-символы (`invoice\u202Egnp.exe`), `/ \ < > : " \| ? *`; на Drive имена случайные; traversal невозможен: путь пользователь не передаёт |
| Обрыв загрузки | Недогруженные файлы удаляются (нет «битых» файлов и утечки места/дескрипторов) |
| Спам / enumeration | CORS-белый список, подписка только на «свой» сайт, honeypot, лимиты по IP, одинаковый ответ для нового и повторного email |
| CSV-инъекции | Ячейки, начинающиеся с `= + - @`, экранируются при экспорте |
| Инфраструктура | HTTPS (TLS 1.2/1.3) + HSTS на публичном домене, контейнер без root, `read_only`, `cap_drop: ALL`, `X-Forwarded-For` перезаписывается nginx |
| Расследования | Журнал: входы, неудачи, блокировки, загрузки, скачивания, публикации, выдача ссылок (IP в журнале через туннель всегда 127.0.0.1) |

Подробный отчёт аудита — в `SECURITY-AUDIT.md`.

## 6. Ограничения Google Drive, о которых надо знать

- Это не CDN: у Drive API есть квоты на запросы и дневной лимит загрузки (~750 ГБ/сутки на аккаунт). Для хранения файлов магазина и админских выгрузок хватает с запасом; для тяжёлого публичного трафика ставьте кэш (Cloudflare) или переходите на S3-совместимое хранилище — драйвер хранилища изолирован в `src/storage/`, добавить S3 можно отдельным файлом.
- Квота 400 ГБ **общая на аккаунт Google** (Gmail, Фото, Drive). Дашборд показывает общую занятость.
- **Делайте бэкап БД**: в `asveli.db` лежит соответствие «имя файла → файл на Drive». Без неё файлы на Drive останутся под случайными именами. Пример ежедневного бэкапа:
  `docker compose exec api node -e "require('better-sqlite3')('/data/asveli.db').backup('/data/backup.db')"` и копирование `backup.db` в другое место.

## 7. GDPR

Вы собираете email из PL/EU/DE. Перед рассылкой добавьте подтверждение подписки (double opt-in) и ссылку отписки; в админке есть удаление и экспорт для запросов «удалить мои данные». IP-адреса подписчиков не сохраняются.

## 8. Модули админки (Internal Admin)

Админка стала полноценной back-office системой на ролях. Модули (меню слева, каждому сотруднику видно только своё):

| Группа | Что внутри |
|---|---|
| **Продавцы и каталог** | продавцы + онбординг/KYC (документы в закрытой области `kyc`), товары (PIM) и модерация с автопроверкой комплаенса, остатки по складам, комплаенс-правила |
| **Логистика** | склады, перевозчики и тарифы, отправления (трек, доставка), возвраты с решением *restock / refurbished / scrap* |
| **Заказы** | покупатели (ПДн зашифрованы), заказы: маршрутизация по складам, налог, сплит комиссии, купон, антифрод — всё в одной транзакции |
| **Финансы и цены** | налоги по странам, книга проводок (единственный источник правды о деньгах), выплаты продавцам с одобрением «двумя ключами», авансы (кредит) с автопогашением из выплат, динамический репрайсер, история цен |
| **Маркетинг и SEO** | рекламные кампании с бюджетом и ROAS, купоны, лояльность, сегменты (когорты) → персональные баннеры, SEO-страницы и аудит |
| **Поддержка** | тикеты L1→L3 (видимость по уровню, SLA, автоэскалация), арбитраж споров, модерация отзывов |
| **Безопасность** | антифрод-правила и сигналы (в т.ч. «скупка остатка конкурентом»), алерты и аномалии, сотрудники/роли/сессии, журнал |
| **Обзор** | аналитика платформы и «кабинет продавца» |

### Роли
`owner, security_admin, catalog_manager, kyc_officer, moderator, logistics, finance, finance_approver, marketing, analyst, support_l1, support_l2, support_l3, fraud_analyst` — матрица прав в `src/iam/permissions.js` и в панели («Сотрудники и доступ»). Доступ запрещён по умолчанию.

```bash
node --env-file=.env scripts/create-admin.js alice --role=owner        # первый владелец
# остальных сотрудников владелец создаёт в панели: логин + роль → временный пароль (показывается один раз, при входе сменить)
```
Существующие админы из прошлой версии автоматически становятся `owner`.

### Персональные данные
Паспорт, IBAN, tax-id, e-mail, телефон, адрес шифруются (AES-256-GCM, привязка к таблице/колонке/строке) ключом `DATA_ENCRYPTION_KEY` и **везде показываются маскированными** (`a***@mail.com`, `•••••67`). Рядом с полем есть кнопка «Показать» — доступна только ролям с правом `pii.reveal`, требует повторного ввода пароля, ограничена по числу в час, блокируется после 5 неверных паролей и пишется в журнал. Номер карты **не хранится вообще** — только бренд и последние 4 цифры (полный номер остаётся у платёжного провайдера, иначе вы попадаете под PCI-DSS).
Простой модератор не видит ни выплат, ни книги проводок, ни ПДн в открытом виде.

### Что реально работает, а что — правила или требует внешних систем
- **Реально и протестировано:** роли и права, шифрование/маскирование ПДн, KYC-блокировки, модерация, заказы (склад/налог/комиссия/купон), книга проводок, выплаты «двумя ключами», авансы, возвраты, споры, тикеты по уровням, аномалии, антифрод.
- **Правила, а не ИИ:** репрайсер, антифрод, аномалии (3σ, ×N), «скоринг» авансов (30% от продаж за 90 дней), персонализация (одно условие на сегмент). Прозрачно и настраивается, но это не ML.
- **Нужны внешние системы (не подключены):** реальные перевозчики (DHL/InPost и т.д. — сейчас тариф и трек вводятся вручную), платёжный провайдер (деньги реально никуда не переводятся: «выплата» — это учёт, перевод делает бухгалтерия/банк), рекламный сервер витрины (статистика кампаний вносится действием «Внести статистику»), сама витрина покупателя и кабинет продавца как отдельный сайт (здесь — внутренний просмотр «Кабинет продавца»). Заказ можно создать вручную в панели или вызвать `POST /api/admin/orders/create` из вашей витрины (через внутренний канал, не публично).
- Одна валюта платформы (`PLATFORM_CURRENCY`), суммы — целые центы. Скидка по купону — за счёт платформы. Позиция заказа не делится между складами.
- Фоновые задачи (аномалии, авто-эскалация тикетов) запускаются каждые 15 минут; отключить: `JOBS=0`.

## 9. Интернет-магазин (витрина + Seller Central)

Витрина лежит рядом: `../storefront` (React + TypeScript + Vite, неоновый стиль по референсам, EN/PL/DE/RU). Она ходит в **публичный** слушатель API (`/api/store/*` для покупателей, `/api/seller/*` для продавцов). Админка по-прежнему только на loopback `:3001`.

### Запуск для разработки
```bash
cd backend
node scripts/create-admin.js aleks                        # один раз
node --env-file=.env scripts/seed-demo.js                 # демо-данные: склады, 4 продавца, ~25 товаров, заказы, отзывы (в production не запускается)
node --env-file=.env src/server.js                        # API :3000, админка :3001
cd ../storefront && npm i && npm run dev                  # http://localhost:5173 (прокси /api → :3000)
```
Демо-входы после seed: покупатель `demo@asveli.test` / `demo-password-123`; продавец `seller@asveli.test` / `seller-demo-12345` (Seller Central: `/seller`). Это только для разработки — удалите/смените перед запуском.

### Что делает магазин
- Главная: персональные подборки (только при согласии на cookie), «продолжить просмотр», тренды, скидки, новинки, реклама (sponsored).
- Поиск: опечатки (fuzzy), подсказки, фильтры (категория, бренд, цена, рейтинг, наличие), сортировка.
- Карточка модели: сравнение предложений продавцов, **Buy Box** (цена + рейтинг продавца + срок + наличие), отзывы только от подтверждённых покупателей, «с этим покупают».
- Корзина/заказ: сервер всегда пересчитывает цены (`expected_total` — защита от устаревшей цены), НДС по стране, доставка по складам, купоны, идемпотентный заказ (двойной клик ≠ два заказа), 1-Click, отмена и возвраты.
- Цифровые товары: мгновенная выдача подписанной ссылки (24 ч) после подтверждения заказа.
- Seller Central: товары (черновик → модерация), заявки на поставку на склад (остаток создаёт только сотрудник при приёмке в админке), заказы без персональных данных покупателей, аналитика, реклама (бюджет не превышается), финансы/выплаты, KYC.
- Антифрод и динамические цены — те же сервисы, что и в админке.
- Приватность: экспорт данных и удаление аккаунта (GDPR), согласие на персонализацию, шифрование ПДн.

### Деплой витрины
1. В `.env` бэкенда: `STORE_ORIGINS=https://asveli.com,https://www.asveli.com`.
2. `cd storefront && VITE_API_URL=https://api.asveli.com npm ci && npm run build`, затем скопировать `dist/` в `/var/www/asveli`.
3. `deploy/nginx-20-storefront.conf` (HTTPS, CSP, SPA-fallback). Заглушки `asveli.pl/.eu/.shop` остаются как есть.
4. Проверки: `npm run typecheck`, `npm run check:i18n`, `cd backend && npm test`.

### Честные ограничения
- **Нет платёжного провайдера**: способы оплаты — «при получении» и «банковский перевод» (только записываются). Карты появятся после подключения Stripe/Przelewy24 и т. п.
- **Нет реальных перевозчиков**: трек-ссылка — шаблон из админки (`tracking_url`), статусы отправок меняет сотрудник.
- Файл цифрового товара прикрепляет сотрудник в админке (публичной загрузки файлов нет специально).
- Документы KYC продавцы загружают не через сайт, а проверяет комплаенс отдельно.
- Юридические страницы (условия, политика, возвраты) — **черновики**, нужна проверка юристом. Переводы PL/DE/RU — машинные, нужна вычитка носителем; кабинет продавца на PL/DE пока показывается по-английски.
- Поисковый индекс — в памяти процесса (десятки тысяч товаров — ок; дальше нужен внешний поиск). Картинки товаров — демо-заглушки (neon-арт), реальные фото задаются URL-ами или публичными файлами.

### Подключение модели (без правки кода)
Админка (через SSH-туннель) → **Интеграции → Подключения AI** (только владелец). Выберите провайдера, вставьте ключ, нажмите **Сохранить** и **Проверить подключение**: изменения действуют сразу, перезапуск не нужен.

| Провайдер | Что делает |
|---|---|
| **Google Gemini** (рекомендуется) | Один запрос читает фото и данные товара и возвращает JSON карточки; тот же ключ даёт поиск по смыслу и картинки для AI Canvas. Ключ: aistudio.google.com/apikey |
| **OpenAI / совместимый** | OpenAI или любой сервер с таким API (OpenRouter, vLLM, LM Studio); для не-OpenAI укажите свой https-адрес |
| **Ollama** | Свой сервер с моделью; адрес во внутренней сети разрешается только флагом `AI_ALLOW_PRIVATE_HOSTS=1` в `.env` |
| **Демо** | Без внешних вызовов, всё помечено как демо |

Там же задаются модели (по умолчанию `gemini-2.5-flash`, `gemini-embedding-001`, `gemini-2.5-flash-image`), дневной лимит вызовов (защита от расходов), таймаут и порог «Требует проверки». Ключ хранится в базе в зашифрованном виде, в браузер не возвращается, в журнал действий не попадает. Значения из `.env` (`AI_PROVIDER`, `AI_API_KEY`, …) — только стартовые; кнопка «Сбросить к настройкам сервера» возвращает их. Без ключа AI-кнопки отвечают понятной ошибкой «AI не подключён».

Адрес API из формы принимается только https и только внешний (внутренняя сеть, localhost и метаданные облака отклоняются), поэтому форму нельзя использовать, чтобы направить сервер внутрь вашей сети.

### Правила, которые не зависят от модели
- **Модель не ставит себе оценку сама.** Уверенность ограничена полнотой входных данных (описание, бренд, штрихкод, внешние источники), и снижается за каждый непроверяемый факт.
- **Факт без источника отбрасывается.** Модель обязана ссылаться на номер из списка доказательств, который выдаёт сервер. Ссылки на что-то другое выкидываются, карточка помечается.
- **Живой товар не снимается с продажи**, когда для него пересоздают карточку: новый текст ждёт проверки человеком. Любая ручная правка текста снимает отметку «проверено».
- **Наружу уходят только одобренные и проверенные** товары.
- Тексты AI хранятся и показываются как обычный текст (в админке нет `innerHTML`).
- Сервер не скачивает страницы поставщиков по ссылке (SSRF). Ссылка сохраняется как источник, а CSV вставляется вручную.

## 6. Shopify: двусторонняя синхронизация товаров

Админка ведёт карточки товаров, Shopify — витрину asveli.com. Синхронизация идёт в обе стороны, без ручного переноса.

**Подключение (один раз, 5 минут).** Админка → **Интеграции → Shopify** (видно только владельцу):
1. <https://dev.shopify.com> → **Apps → Create app** (тот же аккаунт, которому принадлежит магазин).
2. **Versions** → доступы: `read_products, write_products, read_inventory, write_inventory, read_locations, read_translations, write_translations, read_locales` → **Release**.
3. **Home → Install app** → выберите магазин `asveli.myshopify.com`.
4. **Settings** → скопируйте **Client ID** и **Client secret** в админку → «Проверить подключение» → выберите склад Shopify, наш склад и продавца для импорта → «Сохранить».

Старый вариант — токен `shpat_…` приложения, созданного в админке Shopify до 2026 года, — тоже поддерживается. Секреты хранятся в базе в зашифрованном виде (`DATA_ENCRYPTION_KEY`), в браузер и в журнал не попадают. Токен по Client ID / Secret живёт 24 часа и обновляется сам.

**Что и как синхронизируется**

| | Админка → Shopify | Shopify → админка |
|---|---|---|
| Название, описание, бренд, категория, SEO, фото, SKU, штрихкод, вес, цена | да | да |
| Статус | одобрено **и** проверено человеком → Active; снято с продажи → Archived; остальное → Draft | Active в Shopify = одобрение владельца (после комплаенс-проверки); Draft/Archived → черновик / снят с продажи |
| Остатки | доступно (остаток − резерв) нашего склада, запись compare-and-set | продажа в Shopify списывается с нашего склада |
| Новые товары | создаются в Shopify (Draft) | импортируются под выбранным продавцом; совпадение по SKU/штрихкоду — связываются, а не дублируются |
| Удаление | только кнопкой «Удалить в Shopify» с подтверждением `DELETE` | удалённый в Shopify товар снимается здесь с продажи (полная сверка) |
| Переводы | проверенные человеком pl/ru/de → переводы Shopify | — |

- **Когда:** изменение, сохранённое здесь, уходит в Shopify через пару секунд. Изменения из Shopify забираются каждые 5 минут (настраивается), раз в 6 часов — полная сверка. Кнопки «Синхронизировать сейчас», «Полная сверка», «Только отправить», «Только забрать».
- **Конфликты:** у каждой связки хранится состояние обеих сторон на момент последней синхронизации (трёхстороннее слияние). Если одно и то же поле изменили и здесь, и в Shopify, ничего не перезаписывается: товар попадает во вкладку «Конфликты», где видны обе версии и кнопки «Оставить версию админки» / «Взять из Shopify». При первом подключении товара с тем же SKU различия тоже идут в конфликты — ничего не затирается молча.
- **Валюта:** если валюта магазина (PLN) отличается от `PLATFORM_CURRENCY`, нужно указать курс — без него синхронизация не запускается.
- **Товары с несколькими вариантами**, созданные в Shopify: название, описание, фото и статус синхронизируются, цены и остатки вариантов ведутся в Shopify.
- **Права:** настройки и ключи — только владелец (`secrets.shopify`); запуск синхронизации — `shopify.write` (Catalog manager); удаление в Shopify — `shopify.delete` (владелец).
- **Тесты:** `test/shopify.test.js` (12 штук) гоняют всё это против поддельного Shopify в памяти (`test/fake-shopify.js`): создание, правки с обеих сторон, конфликты, гонка «правка во время ответа Shopify», списание продаж, импорт, удаление, валюта, оба способа входа, троттлинг, права.

## 8. Вход покупателей через Google, GitHub и Amazon

В магазине (React) на страницах «Вход» и «Регистрация» появляются кнопки «Войти через Google / GitHub / Amazon» — только для тех провайдеров, которые включены в админке: **Интеграции → Вход покупателей** (видно только владельцу).

**Подключение провайдера.** На той же странице для каждого провайдера показан «Адрес возврата» вида `https://api.asveli.com/api/store/oauth/google/callback` (строится от `PUBLIC_BASE_URL`) и пошаговая инструкция:
- **Google:** console.cloud.google.com → OAuth consent screen (External, Publish) → Credentials → OAuth client ID → Web application → Authorized redirect URIs = адрес возврата.
- **GitHub:** Settings → Developer settings → OAuth Apps → New OAuth App → Authorization callback URL = адрес возврата → Generate a new client secret.
- **Amazon:** developer.amazon.com → Login with Amazon → Security Profile → Web Settings: Allowed Origins = адрес магазина, Allowed Return URLs = адрес возврата (только https).
Скопируйте Client ID и Client secret в админку → «Сохранить». Действует сразу. Магазин, куда возвращается покупатель, выбирается из `STORE_ORIGINS`.

**Как это устроено и почему безопасно**
- OAuth 2.0 authorization code + PKCE (S256) на сервере: client secret не попадает в браузер; `state` одноразовый и живёт 10 минут.
- После входа магазин получает одноразовый код в `#фрагменте` адреса (`/login/callback#code=…`, 2 минуты, хранится только хэш) и меняет его на обычный токен покупателя через `POST /api/store/oauth/exchange` — долгоживущий токен никогда не бывает в URL.
- Первый вход создаёт аккаунт сам (имя и e-mail от провайдера, страна и язык — из магазина). С существующим аккаунтом вход связывается **только если провайдер подтвердил e-mail** (у GitHub — подтверждённый адрес из `/user/emails`); иначе — «войдите паролем и подключите сервис в профиле». Так чужой аккаунт не захватить.
- В профиле: «Способы входа» — подключить ещё один провайдер (одноразовый билет на 2 минуты), отключить. Последний способ входа отключить нельзя, пока не задан пароль. У аккаунта, созданного через провайдера, первый пароль задаётся без «текущего»; удаление такого аккаунта подтверждается словом `DELETE`.
- Секреты провайдеров хранятся зашифрованными, не возвращаются в браузер и не пишутся в журнал.
- Тесты: `test/oauth.test.js` (7) против поддельных Google/GitHub/Amazon; `storefront/src/pages/Auth.test.ts` (3).

**Сайт на Shopify (asveli.com).** Там вход ведёт Shopify, а не этот сервер. На тарифе Basic Shopify умеет Google и Facebook (не GitHub и не Amazon): Shopify → Настройки → Аккаунты покупателей → Способы входа → Google → Connect (нужен свой OAuth-клиент Google с адресом возврата, который покажет Shopify). Затем в редакторе темы → Настройки темы → «Вход покупателей» отметьте «Вход через Google включён» — окно входа на сайте покажет этот способ.

## 9. Данные и бэкапы: внешняя SQL-база и зашифрованные копии

Админка → **Интеграции → Данные и бэкапы** (только владелец, право `secrets.data`). Все данные по-прежнему хранятся и обрабатываются на вашем сервере; модуль добавляет копии.

**Внешняя SQL-база (зеркало).** PostgreSQL, MySQL или MariaDB: вставьте адрес вида `postgres://user:пароль@host:5432/база` или `mysql://user:пароль@host:3306/база`, нажмите «Проверить подключение», затем «Подключить и включить».
- Сначала копируются все таблицы, потом каждое изменение (вставка, правка, удаление) доходит за несколько секунд.
- Изменения записываются триггерами SQLite в той же транзакции, что и сама запись, поэтому не теряются, даже если внешняя база недоступна: они ждут в очереди.
- Новые колонки и таблицы появляются во внешней базе сами.
- Не копируются: сессии, одноразовые токены, учётки сотрудников админки. Свои исключения можно добавить списком.
- Зеркало только для чтения (отчёты, BI, аварийная копия). Всё, что записано в него вручную, перезапишется.
- Пароль базы хранится зашифрованным и не показывается. Лучше дать зеркалу отдельного пользователя с доступом к одной базе.

**Бэкапы.** Онлайн-копия SQLite → gzip → AES-256-GCM, по расписанию (от часа до недели) или кнопкой.
- Хранятся N последних копий на сервере (`data/backups/`). Опционально каждая копия загружается в S3-совместимое хранилище: AWS S3, Cloudflare R2, Backblaze B2, Wasabi, MinIO.
- Со заданным «паролем бэкапа» копию можно восстановить на любом компьютере. Без пароля для восстановления нужен `DATA_ENCRYPTION_KEY` этого сервера.
- Восстановление: `BACKUP_PASSPHRASE='…' node scripts/restore-backup.js копия.asvb restored.db`. Затем остановите сервер и замените `data/asveli.db`.
- Загруженные файлы (`data/blobs` или Google Drive) в копию базы не входят.

Тесты `test/data.test.js` гоняют зеркало на настоящих PostgreSQL и MariaDB (`PG_TEST_URL`, `MYSQL_TEST_URL`; в CI они поднимаются сервисами) и проверяют подпись SigV4 независимой реализацией.

## 10. Рост: наценка, AI-анализ, конкуренты, переводы, агенты, логистика, защита

- **Товары**: закупочная цена, поставщик (с ссылкой), наценка, итоговая цена и прибыль в каждой строке. «Считать цену из закупки + наценки» пересчитывает цену при изменении закупки.
- **Подключения AI**: каталог сервисов с фиксированными адресами (Gemini, OpenRouter, Groq, Cerebras, Mistral, GitHub Models, NVIDIA, OpenAI, Anthropic, DeepSeek, xAI, Together, Ollama, свой сервер). Модели выбираются из живого списка (бесплатные помечены). У каждого сервиса свой ключ. **OpenRouter подключается одной кнопкой** (OAuth PKCE, ключ создаётся сам).
- **AI-анализ товара**: описание, история, рекомендуемая цена. Цена не опускается ниже закупки + 10 % и учитывает только подтверждённые цены конкурентов. Применённый текст уходит на проверку.
- **Цены конкурентов**: поиск в интернете (Gemini Google Search, OpenRouter :online, OpenAI search) по Amazon, Allegro, eBay и др. У каждого предложения ссылка. «Проверено» — только если поиск провайдера реально открыл этот сайт. В `competitor_price` попадают только проверенные точные совпадения в валюте магазина.
- **«Проверить все»** в «Быстрой проверке»: правила (длина, цена, обещания «лучший/гарантия/лечит», замечания AI) + вторая проверка AI против фактов. Подтверждённые помечаются «AI-проверка · пользователь». В демо-режиме автоподтверждения нет.
- **Переводы**: 30 языков, «Перевести всё», автоперевод новых и изменённых карточек (по хэшу исходного текста).
- **API и AI-агенты**: ключи `asv_…` с ролью и сроком (хранится только SHA-256). REST `/api/admin/...` и **MCP `/mcp`** (Streamable HTTP) для Google Antigravity, Claude, Cursor; готовые конфиги на странице. Ключам недоступны секреты, сотрудники, безопасность и раскрытие персональных данных при любой роли. Каждый вызов пишется в журнал.
- **Логистика**: каталог реальных перевозчиков (PL, EU, UK, UA, US…) со ссылками трекинга. Добавляются выключенными, без тарифа не включаются. Склады в любой стране. Карта покрытия по 33 странам.
- **Защита магазина**: цена 0 у товара в продаже, обвал цен, заказ на 0, всплеск 5xx, подбор пароля. При инциденте — тревога, режим «технические работы» (API магазина 503, пуш в Shopify остановлен, метаполе `asveli.maintenance` для темы Shopify), красный баннер в админке. Открывает магазин только человек. Ручное снижение цены на ≥ 50 % требует подтверждения.
- **Фиды для каналов**: Google Merchant (а также Meta, Pinterest, TikTok, Bing), Ceneo, CSV по секретному адресу `/feeds/<token>/…`.
