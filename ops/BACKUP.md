# Перенос данных с серверов OVH на Google Диск

Срок: пробный кредит OVH заканчивается **27 ноября 2026 в 23:26**. Начните сегодня: Google Диск принимает около **750 ГБ в сутки**.
Скрипт ничего не удаляет ни на сервере, ни на Диске.

## 1. Подготовка (один раз, на каждом сервере)

```bash
sudo apt-get update && sudo apt-get install -y zstd sqlite3 tmux
curl https://rclone.org/install.sh | sudo bash      # свежий rclone
```

Скопируйте на сервер файл `ops/backup-to-gdrive.sh` и сделайте его исполняемым: `chmod +x backup-to-gdrive.sh`.

## 2. Подключить Google Диск (вход делаете вы сами, ключ остаётся на сервере)

1. На сервере: `rclone config` → `n` (новый) → имя `gdrive` → тип `drive` → client_id и secret можно оставить пустыми → scope `1` (полный доступ) → остальное Enter.
2. На вопрос «Use web browser to automatically authenticate?» ответьте `n`. rclone покажет команду `rclone authorize "drive" "…"`.
3. Выполните эту команду на компьютере с браузером (там тоже нужен rclone), войдите в Google **аккаунтом с 5 ТБ**, скопируйте полученный ответ и вставьте его обратно на сервере.
4. Проверка: `rclone lsd gdrive:` показывает папки вашего Диска.

Токен — это ключ к вашему Диску. Не пересылайте его в чаты.

## 3. Посмотреть объём (ничего не загружается)

```bash
./backup-to-gdrive.sh plan /путь/к/данным /ещё/папка
```

Покажет число файлов, размер, сколько частей и минимум дней загрузки. Пришлите этот вывод Claude: он без секретов.

## 4. Запустить копирование

```bash
tmux new -s backup            # копирование продолжится, даже если закрыть терминал
./backup-to-gdrive.sh run /путь/к/данным /ещё/папка
```

Выйти из tmux, не останавливая копирование: `Ctrl+B`, затем `D`. Вернуться: `tmux attach -t backup`.

- Данные кладутся в `gdrive:asveli-backup/<имя сервера>/`. Части по 20 ГБ, сжатые (`.tar.zst`), базы SQLite и PostgreSQL отдельно, целостно.
- **Если скрипт остановился** (дневной лимит Диска, обрыв связи, ошибка), запустите ту же команду ещё раз. Готовые части пропускаются.
- Журнал: `/var/tmp/asveli-backup/backup.log`.

## 5. Проверить

```bash
./backup-to-gdrive.sh verify
```

Сравнивает контрольную сумму каждой части на Диске с отправленной. Удалять что-либо на OVH можно только после строки «All … parts match.».

## 6. Восстановить (на новом сервере)

```bash
rclone copy gdrive:asveli-backup/<сервер>/<папка> ./parts
for f in parts/part-*.tar.zst; do zstd -dc "$f" | tar -C /куда -xf -; done
zstd -dc <база>.sqlite.zst > app.db                         # SQLite
zstd -dc postgresql-all.sql.zst | sudo -u postgres psql     # PostgreSQL
```

Каждая часть — самостоятельный архив: её можно восстановить отдельно. Какой файл в какой части, записано в `_index.tar.zst`.

## Настройки

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `REMOTE` | `gdrive:asveli-backup` | куда копировать (для AWS S3 после `rclone config` с типом s3: `s3aws:имя-бакета/asveli`) |
| `PART_GB` | `20` | размер части |
| `ZSTD_LEVEL` | `3` | сжатие: 1 быстрее, 9 сильнее, но медленнее |
| `WORK` | `/var/tmp/asveli-backup` | рабочая папка (списки файлов, журнал) |
